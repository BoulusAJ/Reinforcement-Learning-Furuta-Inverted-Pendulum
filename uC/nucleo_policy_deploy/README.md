# Nucleo Policy Deployment Prototype

This folder is a sidecar prototype for deploying the trained Furuta TD3 actor
on the Nucleo firmware used by the `drehpendel` project. It is intentionally
laid out like a small PlatformIO/mbed project so the pieces can later be copied
or merged into the standalone firmware repository.

The current target policy is:

```text
results/TD3/run_20260618_223832_td3_mathworks_style_pi_current_1b_500hz_long
```

Saved config:

```text
observation dimension: 7
actor shape:           [7] -> [64] -> [64] -> [1]
activation:            ReLU, ReLU, tanh
policy sample time:    0.002 s / 500 Hz
action scale:          normalized [-1, 1], then current = 4 A * action
```

Only the actor is deployed. The TD3 critics are training-only and are not used
on the microcontroller.

Set this in `include/rl_policy_config.h` to compile the prototype in original
drehpendel current-command mode:

```cpp
#define RL_POLICY_CONTROLLER_ENABLE 0
```

This is the safe default for the prototype. With this flag disabled, the NN policy thread and generated weights are not
compiled, the UART response is the original 3-float response, and the host
`current_cmd` input drives the current loop.

## Intended Workflow

1. Load the final TD3 agent in MATLAB.
2. Export the actor weights into `lib/RLPolicy/rl_policy_weights.h`.
3. Verify the raw MATLAB forward pass matches `getAction(getActor(agent), obs)`.
4. Copy/merge the C++ pieces into the `drehpendel` firmware. The
   `lib/realtime_thread` files intentionally keep drehpendel's base naming and
   loop structure, with only the RL policy additions layered on top.
5. First run in shadow mode: compute policy on the Nucleo and send the policy
   action/current back over UART while the host/SLDRT still commands current.
6. Only after shadow mode matches MATLAB/SLDRT, enable onboard policy current
   output with strict current and angle limits.

See `docs/deployment_workflow.md` for details.
